Support и возвраты

Проверка документов и runtime показывает: базовые документы/макеты есть, но support/refund для платной Nebula-консультации не готов как управляемый процесс.

частично: документы есть, workflow не доказаннельзя запускать checkout/traffic

Итог по ячейке

1. Как должно быть

Клиент видит путь обращения до/после оплаты. Support видит order, paid session, transcript, SLA, причину обращения, refund decision, audit log и evidence export.

2. Документы / фронт

В Oracle/Nebula есть макеты Contact, FAQ, Payment Terms, Privacy, Refund Policy, Terms, Cookie Policy. Но они брендированы Neuro и не доказаны как live/legal-approved Nebula docs.

3. Бек / админка

Runtime gap G09: support/refund частично есть только как surface. Нет доказанного Nebula workflow: case → order/session/transcript → decision → refund/evidence.

Что проверено

Live Confideline documents
  • Есть live: /en/page/terms-and-conditions, /en/page/privacy-policy, /en/page/cookie-policy.
  • Не найдены на проверенных URL: refund-policy, payment-terms, contact-us, faq.
  • Terms и Cookie показывают dating/legacy leakage. Это нельзя пускать в Nebula paid traffic.
Oracle/Nebula documents
  • Есть локально: contact-us, FAQ, payment terms, privacy, refund policy, terms, cookie policy.
  • Есть refund/support mentions.
  • Проблема: бренд Neuro, нет финального legal approval, нет доказанной связи с backend support/refund.

Чего не хватает

Public docs

Опубликовать/подключить Nebula-ready Contact, FAQ, Payment Terms, Refund Policy, Terms, Privacy, Cookie. Убрать dating/adult/subscription leakage. Заменить Neuro на финальный бренд/рабочий Nebula wording.

Refund rules

Зафиксировать refund window, причины возврата, кто принимает решение, SLA review, что видит клиент, что видит support/finance.

Admin workflow

Сделать/проверить очередь support cases: reason, customer, order, session, transcript, advisor, SLA, decision notes, refund status, audit log, evidence export.

Payment link

Связать receipt/checkout с support/refund path: клиент из заказа должен открыть обращение, а support должен видеть конкретный order/session.

RBAC

Проверить роли support, finance, moderator, advisor ops: кто видит transcript, кто меняет refund status, кто экспортирует evidence.

QA proof

Сценарий приемки: test order → paid session → client support request → support sees evidence → refund decision recorded → client-visible status → audit/evidence export.

Следующая задача для программиста / PM

Название

Support/refund evidence workflow для Nebula paid consultation.

Scope

Адаптировать support module под Nebula: case reasons, refund taxonomy, order/session link, transcript/evidence bundle, support SLA, internal decision notes, customer-visible status.

Готово когда

Support/refund scenario PASS: клиент видит путь обращения; support видит order/session/transcript; refund decision фиксируется; evidence export доступен.

Стоп-условие

Не запускать paid traffic и не публиковать checkout как готовый, пока support/refund workflow и public docs не пройдут проверку.
